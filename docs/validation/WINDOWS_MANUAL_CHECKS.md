# Windows native accessibility checks

**Owner checklist — not executed by the agent.** Browser-native zoom/reflow and Narrator/NVDA remain unverified. The [four failed native-control attempts](evidence/f2-native-attempts.json) are preserved; no further repetitions of the inaccessible automation channel are planned. Completing this guide does not itself close Phase 5 or the MVP.

1. **Prepare.** Follow the [README local setup](../../README.md#local-setup), start PostgreSQL, API and React, and seed a fresh reading in a disposable development database. Open the Vite address (normally `http://localhost:5173`). Record commit, Windows/browser versions, Windows display scaling and reader/version. Start with the ordinary seed (1,200 W / 800 W / 65%); note which zero/large-value or sparse observations are actually available. Do not clear valuable data.
2. **Use native zoom.** In Chrome's three-dot menu, set the site's **Zoom** to **100%, 200%, then 400%**; record the displayed percentage and a screenshot at each level. Measure the effective CSS viewport in undocked DevTools with `({width: innerWidth, height: innerHeight, dpr: devicePixelRatio})`. Aim for about 1280 CSS px at 100% and verify, rather than assume, about 320 CSS px at 400%. DevTools device emulation, CSS/font-size changes, magnification and pinch zoom are different checks. [Chrome's official zoom instructions](https://support.google.com/chrome/answer/96810?co=GENIE.Platform%3DDesktop&hl=en).
3. **Check reflow.** At each zoom level navigate Overview → History → Installation. Use Tab/Shift+Tab and Refresh. In History verify complete numeric values and W/% units, visible focus, reachable charts/−1/+1 controls and vertical scrolling without page-level horizontal overflow or sticky content obscuring the active control. Select a missing minute with −1/+1: it must be unavailable, not zero or a nearby reading. Record zero/large-value cases as not run if the chosen data set does not contain them.
4. **Listen with a real reader.** Return to 100% and start Narrator with **Windows+Ctrl+Enter**, or use Windows Settings → Accessibility → Narrator; use an already installed NVDA instead if preferred. Tab through section links/Refresh, then History's plots and minute controls. Listen for meaningful names, units/date, selected values and the missing-minute message. On a focused History plot, Home/End select first/last observations and Left/Right inspect records. If Narrator scan mode consumes those keys, toggle it with **Narrator key+Spacebar** (Caps Lock or Insert by default), note the mode, and restore it afterward. [Start/stop Narrator](https://support.microsoft.com/en-us/accessibility/windows/narrator/chapter-1-introducing-narrator); [scan-mode instructions](https://support.microsoft.com/en-us/accessibility/windows/narrator/chapter-3-using-scan-mode).
5. **Listen during Refresh and recovery.** Check idle → Refresh pending → success: progress must reflect actual requests and must not remain announced as current at rest. To test error/retention, stop only your disposable test API with Ctrl+C in its terminal, press Refresh, listen to the retained/error message, restart the API with the README command and Retry. Previous values must remain qualified until recovery. Observe mixed and both-pending states if feasible (temporary DevTools throttling can help); mark any unobserved transition as not run, never inferred from the automated AX tests. Label the API interruption as a controlled test outage.

Use **Pass**, **Fail** or **Not run** per executed case; an AX-tree snapshot is not spoken reader evidence. A confirmed unreadable required value or inaccessible required control blocks closure until addressed. Remaining risks are native clipping/occlusion and reader-specific reading/focus order, control interpretation or missing/duplicate announcements. Unexecuted checks require explicit owner disposition, not an assumed pass. Physical-phone browser chrome/safe-area behavior also remains outside the executed desktop/emulated checks.
