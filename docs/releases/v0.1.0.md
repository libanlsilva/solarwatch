## Included scope

- One residential installation, with all measurements explicitly identified as **simulated**.
- PostgreSQL persistence, ASP.NET Core 10 APIs for Latest Reading and inclusive server-referenced 24-hour history, and a React/TypeScript interface.
- Approved dark responsive Overview, History and Installation: solar generation and household consumption in **W**, battery charge in **%**, local measurement dates/offsets, and freshness based on the last successful server `asOf`.
- Real elapsed-time charts with separate power/charge scales, valid zero readings, original UTC microseconds, irregular samples and missing-data gaps. No fabricated values or interpolation across gaps over five minutes.
- Shared exact-observation/UTC-minute History selection, synchronized plots/panel, keyboard inspection, minute buttons and mobile touch controls.
- Manual Refresh, independent Latest/History requests, loading/empty/error/retry/refreshing/retained-data states and correct stale-data qualification.
- Local Development-only HTTP ingestion with validation and PostgreSQL-enforced duplicate conflicts; no overwriting existing readings.
- Finite/continuous simulators and exactly 1,441 historical samples over an inclusive 24-hour range. Optional deterministic `residential-v1` supplies coherent synthetic day/night solar, variable demand and gradual battery changes; original random behavior remains available.

## Run and reproduce

Prerequisites: Git, **.NET 10 SDK**, **Node.js 24/npm**, Docker with Linux containers/Compose, and access to public package/browser sources. PostgreSQL runs in Compose; .NET/React run on the host, following accepted [ADR-001](https://github.com/libanlsilva/solarwatch/blob/v0.1.0/docs/architecture/adr-001-local-startup.md). Full-stack Compose is deliberately not a release prerequisite.

Follow the [isolated clean-clone setup](https://github.com/libanlsilva/solarwatch/blob/v0.1.0/docs/development/CLEAN_CLONE.md), stopping before its seed/random-history steps when preparing the residential demonstration. Use a **new project/volume, fresh ignored credentials and unused loopback ports**, then the [residential-v1 preparation recipe](https://github.com/libanlsilva/solarwatch/blob/v0.1.0/docs/architecture/residential-history-profile.md#prepare-an-isolated-empty-demonstration). Capture a current server UTC reference, keep its original string, and use seed 42. The simulator never resets or overwrites an existing dataset. Stop services normally; retain the named volume and original configuration.

See the [final candidate validation and repeatable smoke commands](https://github.com/libanlsilva/solarwatch/blob/v0.1.0/docs/validation/LOCAL_MVP.md). The [approved demonstration guide](https://github.com/libanlsilva/solarwatch/blob/v0.1.0/docs/demo/README.md), [six definitive captures](https://github.com/libanlsilva/solarwatch/blob/v0.1.0/docs/demo/GALLERY.md) and original [manifest](https://github.com/libanlsilva/solarwatch/blob/v0.1.0/docs/demo/manifest.json) remain unchanged historical evidence at their recorded baseline. ## Verification and known limitations

The [final acceptance record](https://github.com/libanlsilva/solarwatch/blob/v0.1.0/docs/validation/LOCAL_MVP.md) maps all twelve MVP criteria, the isolated current-candidate installation, existing 277 tests, security/documentation checks and the GO/NO-GO recommendation. Final PR checks and any authorized post-integration checks must identify their exact commits; an earlier green run does not approve a later runtime change.

- **Local demonstration only.** APIs are unauthenticated. Keep PostgreSQL, API and frontend bound to loopback; ingestion additionally requires Development and the existing direct-local request checks. A public source repository is not a public running service. These notes are not a production deployment, tunneling or reverse-proxy guide, security certification or authorization to expose the application.
- `residential-v1` uses a fixed fictional UTC schedule, reproducible seed phases and a simplified lossless battery balance with an assumed 10 kWh capacity / ±2 kW rate and 50% starting charge per window. No measured battery/grid flows, accumulated-energy totals, real weather, forecasts, profits or physically complete model are supplied.
- Live history windows advance with the server. Freshness is evaluated at the last successful server check; screenshots do not remain fresh indefinitely. There is no polling, SignalR, real hardware, authentication or multiple-installation/user support in this scope.
- Native Chrome/Edge zoom at 100/200/400%, Narrator/NVDA and physical mobiles remain **unverified**, with their risks expressly accepted by the owner for this local portfolio release only. They are not passed checks or accessibility certification. Preserve the [acceptance limits](https://github.com/libanlsilva/solarwatch/blob/v0.1.0/docs/validation/PHASE5_ACCEPTANCE.md) and [Windows manual procedures](https://github.com/libanlsilva/solarwatch/blob/v0.1.0/docs/validation/WINDOWS_MANUAL_CHECKS.md).
