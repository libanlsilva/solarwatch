# SolarWatch v0.2.0 — live telemetry

Plan: [v2-realtime-plan.md](../architecture/v2-realtime-plan.md). Issues #47–#51.

## What is new
| Delivery | PR | Summary |
|---|---|---|
| Simulator | #52 | `--continuous --profile residential-v1 --interval-seconds 1..60`: a continuous residential profile, battery continuing from the latest stored charge. |
| Electrical parameters | #53 | Optional `gridVoltageV`, `gridFrequencyHz`, `inverterTemperatureC`, `batteryVoltageV` (validated ranges, nullable columns, migration `AddElectricalParameters`). |
| SignalR | #54 | Hub `/hubs/readings`, event `reading`; best-effort publish after a successful POST ([doc](../architecture/live-readings-hub.md)). |
| Live UI | #55 | SignalR client with reconnect and HTTP resync, rolling 5-minute chart, derived power-flow diagram, electrical panel, animated numbers, live toggle, reduced motion ([doc](../architecture/live-ui.md)). |

## Demo
```sh
docker compose up -d --wait postgres
dotnet run --project backend/src/SolarWatch.Api            # http://localhost:5171
dotnet run --project simulator/SolarWatch.Simulator --configuration Release --no-build -- --continuous --profile residential-v1 --interval-seconds 2
npm --prefix frontend run dev                               # http://localhost:5173
```

## Known limitations
- A 1–2 s cadence stores tens of thousands of rows per day, so the History payload grows accordingly.
- The `residential-v1` history profile has no electrical fields.
- Battery power in the flow diagram is derived (solar minus home), not measured.
- Events missed while offline are not replayed; the app resynchronizes over HTTP on reconnect.
- PR #52 merged before its CI registered; main CI after it was subsequently green.
- No screenshots were captured for this release; native screen-reader and physical-device checks remain unverified, as in v0.1.0.
